# FOG-ORCHESTRATOR 2.0 — PHYSICAL VS EMULATED PAYLOAD AUDIT

**Date**: 2026-08-29  
**Author**: Principal Systems Architect, Industrial IoT Verification Lead  
**Scope**: Field-by-Field Comparison of Manual, Emulated, and Real Physical ESP32 Relay Payloads

---

## 1. Executive Summary

This audit compares three payload variants processed by the HMI Backend ingestion endpoint `POST /api/hardware/telemetry`:
1. **Manual Payload**: Synthetic test JSON used during early REST API unit tests.
2. **Emulator Payload**: Software test payload generated by `verify_wireless_hmi.py`.
3. **Physical Payload**: Real telemetry packet transmitted by ESP32 TRUCK_01 over LoRa V2V, received and relayed by ESP32 TRUCK_02 over Wi-Fi HTTP POST.

## 3. Physical Firmware Invariant

The ESP32 Vehicle B (`TRUCK_02`) relay payload schema remains **100% UNTOUCHED**:
```json
{
  "vehicle_id": "TRUCK_01",
  "sequence": 42,
  "rpm": 0.00,
  "speed": 0.00,
  "accel_x": -364,
  "accel_y": 220,
  "accel_z": 16920,
  "gyro_x": 584,
  "gyro_y": 398,
  "gyro_z": 191,
  "rssi": -87,
  "snr": 9.50,
  "source": "V2V_VIA_TRUCK_02"
}
```

The HMI Backend ingestion layer now accepts both legacy `ax`/`gx` schemas and physical `accel_x`/`gyro_x` relay payloads without firmware changes.
