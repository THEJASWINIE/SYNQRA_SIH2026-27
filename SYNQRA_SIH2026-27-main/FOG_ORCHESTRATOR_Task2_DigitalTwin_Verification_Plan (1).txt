1. Purpose
This plan verifies that the Task 2 Digital Twin correctly represents the approved FOG-ORCHESTRATOR architecture, preserves physical consistency, reproduces expected cause-and-effect relationships, and provides trustworthy interfaces to Task 1 HMI and Task 3 hardware-in-the-loop.
2. Verification philosophy
Verification asks: “Did we implement the model correctly?”
Validation asks: “Does the model behave credibly for the intended operational use?”
Every major result must be classified as mathematical proof, simulation demonstration, HIL validation or field validation.
Simulation output shall not be presented as NMDC field performance.
Critical safety-model defects require correction and re-execution before acceptance.

8. Uncertainty / Monte Carlo plan
At least 1,000 runs for initial stress tests; increase when computationally practical.
Randomize mass, grade, friction, visibility, forecast error, latency, packet loss, service rates and fleet size.
Use fixed random seeds for benchmark reproducibility.
Report mean, median, P5, P95, worst-case, standard deviation and safety-violation probability.
Do not claim field distributions unless source-backed.
Include correlated fog/friction scenarios; also run independence as a sensitivity baseline.

10. Interface verification
Task 1 HMI receives road, vehicle, queue, bottleneck, safe speed, risk, dispatch and slot state with valid timestamps.
Task 3 telemetry packet can replace simulated state without breaking the digital-twin API.
Stale telemetry triggers timeout/confidence reduction.
Units are consistent: m, s, m/s, kg, N, W, vehicles/hour.
Every command has timestamp, source, validity interval and mode.

12. Acceptance gates
Gate A — Mathematical: all critical equations pass dimensional, sign and monotonicity tests.
Gate B — Network: queues, buffers and bottlenecks behave as intended.
Gate C — Optimization: baseline comparisons and ablations are reproducible.
Gate D — Safety: no modeled safety-envelope violations in accepted hybrid scenarios.
Gate E — Performance: 50-vehicle benchmark completes with measured timing.
Gate F — Interface: Task 1 and Task 3 interfaces pass integration tests.
Gate G — Reproducibility: benchmark result regenerated from saved scenario/config/seed.
Gate H — HIL readiness: simulated vehicle telemetry can be swapped for real Task 3 telemetry.

14. Exit criterion
Task 2 is COMPLETE only when all mandatory requirements are mapped to passed verification evidence, all critical defects are closed, the benchmark results are reproducible, and the digital twin can exchange state/commands with Task 1 HMI and the future Task 3 HIL interface.
