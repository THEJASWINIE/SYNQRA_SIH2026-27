1. Purpose
Define the complete, testable requirements for the FOG-ORCHESTRATOR Digital Twin. The twin is the predictive operational model connecting mine-road conditions, vehicle states, weather/fog, road capacity, queues, bottlenecks, dispatch decisions and physical safety constraints. The core objective is to provide a deterministic and reproducible simulation environment that can later accept live telemetry from Task 3 hardware.
2. Scope and boundary
Core twin is graph-based, event/time-stepped and physics-aware; a photorealistic 3D mine is not required for the MVP.
The twin must represent mine roads, grades, geometry, intersections/switchbacks, shovels, crushers/dump points, buffers/queues, vehicles, fog/visibility, friction/road condition and communications.
The twin must support deterministic scenario replay and stochastic/Monte Carlo experiments.
The twin is not a substitute for field survey data. Representative mine geometries and parameter ranges shall be explicitly labelled as assumptions.
No safety claim shall be interpreted as field certification. Outputs are model/simulation evidence until hardware and field calibration.
3. Design principles
Physics first: vehicle equations remain the source of safety constraints.
Separation of concerns: environment, vehicle, traffic, optimization and visualization are modular.
Reproducibility: scenario files, seeds and model versions must be recorded.
Fail-safe simulation: invalid or missing state must not create optimistic safe-speed outputs.
Model transparency: every state variable and derived quantity must be traceable.
HIL-ready interfaces: simulated telemetry must use the same schema expected from Task 3.
4. System architecture
Environment Model → Vehicle Dynamics → Perception/Uncertainty → Road Capacity → Queue/Network → Bottleneck State → Fleet Optimizer → Slot/Dispatch Commands → Vehicle State Update → Digital Twin synchronization.

6. Non-functional requirements
ID
Quality attribute
Requirement
NFR-001
Determinism
Same model + scenario + random seed produces identical results.
NFR-002
Time resolution
Core physics/network simulation supports configurable step <= 1 s for HIL-facing scenarios.
NFR-003
Scale
50 vehicles minimum without state corruption or dropped events.
NFR-004
Performance
Scenario simulation shall run faster than real-time for normal SIH scenarios where practical; timing shall be reported rather than assumed.
NFR-005
Traceability
Every computed KPI can be traced to logged inputs and model version.
NFR-006
Modularity
Environment, vehicle, queue, optimizer and visualization components can be tested independently.
NFR-007
Units
Internal SI units; display conversion only at interface layer.
NFR-008
Numerical safety
No NaN/Inf/negative physical states may silently propagate.
NFR-009
Fail-safe
Missing/stale safety-critical data forces conservative mode in the simulation.
NFR-010
Interoperability
Telemetry schema supports JSON/CSV/MessagePack or equivalent documented format.
NFR-011
Reproducibility
Scenario/config/seed/result bundle is sufficient to reproduce a benchmark.
NFR-012
Visualization independence
Core twin shall function without 3D rendering.

10. MVP completion criteria
A 10–50 vehicle digital twin reproduces all mandatory scenario types.
The twin produces v_safe, H_safe, C_r, queue and bottleneck state consistently.
Arrival-rate shaping and switchback reservation can be demonstrated in simulation.
Fog and friction changes propagate through physics → capacity → queue → dispatch.
Task 1 HMI receives live simulation state.
Task 3 telemetry can replace simulated vehicle state without changing the core twin model.
All mandatory V&V tests pass with documented evidence and no unresolved critical defects.
