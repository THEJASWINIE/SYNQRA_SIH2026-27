1. PROJECT ORIENTATION — WHAT ARE WE ACTUALLY BUILDING?
FOG-ORCHESTRATOR is not a fog detector and not merely a vehicle speed controller. It is a mine-traffic decision system that predicts how degraded visibility and road condition change the safe operating capacity of haul-road segments, propagates that degradation through queues and bottlenecks, and coordinates fleet releases, routes and road slots while each vehicle independently enforces a physics-based safety floor.
WEATHER / VISIBILITY / ROAD CONDITION                 ↓        VEHICLE + ROAD PHYSICS                 ↓       SAFE SPEED / SAFE HEADWAY                 ↓          ROAD CAPACITY C_r                 ↓       QUEUE / BOTTLENECK STATE                 ↓        FLEET DISPATCH / SLOTS                 ↓        VEHICLE COMMAND TARGET                 ↓       REAL / SIMULATED VEHICLES                 ↓            TELEMETRY LOOP
Core architectural ruleTier 3 decides where/when vehicles should be dispatched. Tier 2 coordinates conflicts on constrained road sections. Tier 1 decides whether a requested movement is physically safe. Central optimization must never override the local physics safety governor.

4. PHYSICS MODEL — THE FOUNDATION OF THE TWIN
The digital twin must not use a visually convenient kinematic model alone. It must expose the same physics quantities used by the FOG-SAFE safety governor so that later Task-3 hardware telemetry can replace simulated signals.
4.1 Longitudinal force balance
m * dv/dt = F_drive + m*g*sin(theta) - F_roll - F_aero - F_retarder - F_brake
Term
Equation
Meaning
Grade force
F_grade = m g sin(theta)
Gravity component along downhill direction
Rolling resistance
F_roll = C_rr m g cos(theta)
Road/tire rolling resistance
Aerodynamic drag
F_aero = 0.5 rho C_D A v^2
Air drag; can be neglected in conservative stopping calculation
Tire traction limit
F_mu = μ m g cos(theta)
Maximum longitudinal tire-road force before slip

4.2 Braking / deceleration model
F_available = min(F_hardware_max, mu * m * g * cos(theta))m*a_x = m*g*sin(theta) - C_rr*m*g*cos(theta) - F_aero - F_retarder - F_brake
For conservative emergency stopping, aerodynamic drag is not credited as a constant braking force all the way to zero speed; the current validated implementation evaluates stopping deceleration conservatively without relying on full-entry-speed aero drag. Hydraulic/brake buildup latency is explicitly included in total reaction latency.
4.3 Stopping distance
d_reaction = v * tau_totald_brake    = v^2 / (2*a_dec)S_stop    = d_reaction + d_brakeSafety condition:S_stop + S_margin <= R_effective
4.4 Total latency
tau_total = tau_sensor + tau_communication + tau_decision + tau_human + tau_hydraulic
Current audit configuration increased the ECU/hydraulic component to approximately 0.25 s as a conservative prototype parameter. The exact hardware value must be replaced by measurement during Task 3.
4.5 Safe-speed solution
v_safe = min(v_stop, v_retarder, v_traction, v_curve, v_mine)v_command = min(v_dispatch, v_safe)
The dispatch system is never allowed to request a speed above the local physics ceiling. This separation is mandatory.
4.6 Downhill retarder constraint
For continuous downhill operation:P_ret_required = F_ret_required * vRequire:P_ret_required <= P_ret_max
Emergency stopping and continuous downhill sustainability are separate constraints. Do not substitute one for the other.
4.7 Friction estimation boundary
Normal steady-state micro-slip operation does not fully identify peak friction. The research recommends using an environmental prior, coasting to separate rolling resistance, and informative braking/retarding events to update μ. The safety engine uses a conservative lower confidence bound rather than an optimistic mean.
mu_safe = max(mu_floor, mu_hat - k_sigma * sigma_mu)Research reference configuration:mu_floor ≈ 0.18k_sigma ≈ 1.645 for a 95% one-sided bound
These are configuration values from the current research model, not measured NMDC field values.
5. FROM VEHICLE PHYSICS TO MINE PRODUCTIVITY
This is the key innovation bridge. The digital twin transforms vehicle-level constraints into road capacity, then into queues, bottlenecks and fleet actions.
Vehicle physics    ↓v_safe, H_safe    ↓Road capacity C_r    ↓Arrival rate lambda, service rate mu    ↓Queue Q    ↓Bottleneck score    ↓Dispatch / departure slots / route choices    ↓Production
5.1 Initial road-capacity model
First-order analytical model:C_r ≈ v_safe / H_safe   [vehicles/second]Convert to vehicles/hour:C_r_h = 3600 * v_safe / H_safe
The model must enforce physical headway. Current validation uses a minimum center-to-center spacing of approximately vehicle length + standstill margin = 15.5 m for the BH100-class reference configuration. This prevents impossible packing. The team should keep the capacity model modular so it can later incorporate directionality, road width, opposing traffic and conflict zones.
5.2 Queue dynamics
Q_j(t + dt) = max(0, Q_j(t) + A_j(t) - D_j(t))D_j(t) <= service_rate_j(t)rho_j = lambda_j / mu_jrho_j > 1  -> unstable queue growth
5.3 Bottleneck score
BottleneckScore_j = f(utilization, queue, criticality)Prototype form:B_j = (w1*rho_j) * (1 + w2*Q_j) * (w3*Criticality_j)
Do not treat the numerical weights as truth. Make them configuration values and verify by ablation. The current hierarchy used for prototyping is crusher > shovel > intersection > haul road, but the twin must be able to discover bottleneck migration rather than permanently forcing a ranking.
5.4 Arrival-rate shaping
lambda_arrival(t) <= mu_node(t) - delta_buffer
The optimizer controls truck release timing, assignment and route so that downstream service nodes are not flooded. Holding a truck at a shovel or buffer can be preferable to creating a downstream queue that blocks the network.

8. FLEET OPTIMIZATION MODEL
The Tier-3 optimizer is a receding-horizon decision layer. It does not directly command motor PWM. It assigns routes, departure times, slots and target operating states while Tier 1 enforces local physical feasibility.
8.1 Objective
maximize expected production over horizon H      - bottleneck penalty      - queue/delay penalty      - risk penalty
8.2 Chance-constrained form
P(v_i(t) <= v_safe_i(t)) >= 0.99P(flow_r(t) <= C_r(t)) >= 0.95P(Q_j(t) <= Q_max_j) >= 0.95
These probabilities are model constraints, not field safety guarantees. If the chance-constrained solver becomes impractical, use scenario-based robust MPC or deterministic MPC with conservative bounds.

9. SWITCHBACK / INTERSECTION MODEL
A switchback/intersection is a shared conflict resource. Vehicles announce ETA; an RSU/tactical controller allocates non-overlapping occupancy windows. The slot system is a traffic-coordination mechanism, not a replacement for the local safety governor.
Vehicle A: ETA_A, clearance_AVehicle B: ETA_B, clearance_BAllocate:slot_A = [tA_start, tA_end]slot_B = [tB_start, tB_end]Constraint:slot_A ∩ slot_B = ∅ for conflicting movements
The exact priority policy must be configurable. Do not hard-code “downhill always wins” as a universal safety law; use a testable priority rule based on stopping difficulty, vehicle state and conflict geometry.
