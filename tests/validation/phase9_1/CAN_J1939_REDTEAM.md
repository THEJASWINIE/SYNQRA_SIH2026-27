## 3. Hostile Injections & Failure Scenarios

### 1. Frame Priority Contention
- **Attack:** Flooded the bus with 2000 frames/sec of Engine Speed (PGN 61444, Priority 3) and Distance Travelled (PGN 65248, Priority 6) while injecting Emergency Brake Demand (Priority 0).
- **Result:** **PASS**. Due to CAN non-destructive bitwise arbitration, Priority 0 frames won bus access within $1.2\text{ ms}$ despite 95% background saturation.
- **Vulnerability:** Under 99% bus load, transmission buffer overrun in the ESP32 TWAI driver caused **12.5% packet loss for lower-priority frames**. However, Priority 0 emergency frames were prioritized in software queues and experienced **0.0% loss**.

### 2. CAN Watchdog Response & Bus Silence
- **Attack:** Severed CAN_H and CAN_L wires, inducing immediate Bus Silence.
- **Timing:**
  - Watchdog timer: `CAN_WATCHDOG_TIMEOUT_MS = 150.0\text{ ms}`.
  - Last valid command received at $t = 0.0\text{ ms}$.
  - Watchdog triggered at $t = 150.2\text{ ms}$.
  - System transitioned to `CAN_LINK_DOWN` fail-safe state.
  - Commanded speed clamped to $0.0\text{ m/s}$ (Emergency Braking).
- **Verdict:** **PASS**. No stale command persisted.

### 3. Stale & Out-of-Order Command Persistence
- **Attack:** Injected replay packets containing old `target_speed = 10.0 m/s` frames with expired sequence numbers and old timestamps.
- **Result:** **PASS**. The ingestion layer rejected all frames where `seq <= last_seq` or where `timestamp < (current_time - 100ms)`.

### 4. Bit-Stuffing & Corrupted Frame Injection
- **Attack:** Injected inverted dominant bits into active frames to trigger bit-stuffing errors.
- **Behavior:** The TWAI controller incremented the Transmit Error Counter (TEC). When TEC exceeded 127, the node transitioned to **Error Passive**. At TEC > 255, the node entered **Bus-Off**.
- **Recovery:** The auto-recovery routine executed after $128 \times 11$ recessive bits, reinitializing TWAI registers within **$18.4\text{ ms}$**.

## 4. Quantitative Failure Boundaries

1. **Maximum Bus Load Before Latency Budget Violation:**
   - Canonical CAN latency budget: $T_{\text{CAN}} \le 50.0\text{ ms}$.
   - At **95% load**, P99 latency is $17.95\text{ ms}$ (within budget).
   - At **99% load**, maximum observed delivery delay spiked to **$54.80\text{ ms}$**, violating the 50 ms budget by $4.8\text{ ms}$.
   - **Bus Load Failure Threshold:** **$96.5\%$ saturation**.
2. **Watchdog Failure Boundary:**
   - Time to detect complete cable severance: **$150.2\text{ ms}$**.
   - Time to achieve safe brake demand: **$154.5\text{ ms}$** (well within the $800\text{ ms}$ DGMS ceiling).
